# 관리자 가이드

관리자는 공유 지식 폴더(RAG 루트)를 만들고, 임베딩 모델을 배치하고, 색인을 갱신하고, 애드인을 게시합니다. 팀원은 색인을 만들지 않고 공유 폴더의 완성된 색인을 로컬 캐시로 복사해 검색만 합니다.

---

## 1. 공유 폴더 구조

```
\server\KB\                      ← 설정의 "RAG 루트"
  products.json                   ← 제품군 id/표시명/폴더/분류 키워드 (팀 공용)
  _common\ ...                    ← 라이선스·설치 등 공통 (모든 제품 검색에 함께 포함)
  LS-DYNA\
    _prompt.md                    ← 제품별 답변 지침·용어·금지사항
    manuals\*.pdf   replies\*.msg|*.eml   faq\*.md|*.docx|*.txt   issues\*.xlsx|*.csv
  Ansys-Fluent\ ...
  _index\
    manifest.json                 ← 임베딩 모델 id·차원·제품별 색인 버전/해시/빌드시각
    LS-DYNA.sqlite, Ansys-Fluent.sqlite, _common.sqlite ...
  _models\bge-m3-int8\            ← model.onnx, sentencepiece.bpe.model
```

- 제품 폴더 안의 하위 폴더 이름으로 문서 유형이 정해집니다. `replies`의 과거 답변 메일은 **답변 문체 예시**로, 나머지(`manuals`, `faq`, `issues` 등)는 **근거 자료**로 쓰입니다.
- 색인하지 않는 파일: `_prompt.md`, `~$`로 시작하는 Office 임시 파일, `.`으로 시작하는 숨김 파일, 이름이 `_` 또는 `.`으로 시작하는 폴더 안의 파일.
- 지원 형식: PDF, DOCX, XLSX, CSV, MSG/EML, TXT, MD. 그 외 형식은 색인하지 않고 Indexer가 개수를 알려 줍니다.
- `_index`는 Indexer가 만듭니다. 직접 수정하지 마세요.
- 샘플은 저장소의 `samples\kb`에 있습니다(처음 시험할 때 복사해서 쓰면 됩니다).

## 2. Indexer 준비와 폴더 만들기

Indexer(`TechSupportReply.Indexer.exe`, .NET Framework 4.8 콘솔 프로그램)는 저장소에서 빌드합니다.

```powershell
dotnet build src\TechSupportReply.Indexer -c Release
```

산출물은 `src\TechSupportReply.Indexer\bin\Release\net48\` 폴더입니다. 이 폴더 전체(onnxruntime.dll, e_sqlite3.dll 포함)를 `C:\Tools\TechSupportReply.Indexer` 같은 관리 PC 폴더로 복사해 사용합니다.

### 명령 요약 (Indexer 도움말 그대로)

```
사용법: TechSupportReply.Indexer <명령> [옵션]

  init-kb --root <공유 폴더>
      지식 폴더 구조, products.json, 제품별 _prompt.md 템플릿을 만듭니다.
  index   --root <공유 폴더> [--product <id>] [--full] [--model <모델 폴더>] [--work <작업 폴더>]
      제품 폴더를 색인해 _index에 게시합니다(바뀐 파일만 다시 임베딩).
  search  --root <공유 폴더> --product <id> --query <텍스트> [--top 8] [--cache <폴더>]
      애드인과 같은 방식으로 캐시를 동기화하고 검색 결과를 보여 줍니다.
  reply   --root <공유 폴더> --mail <파일.txt|.eml|.msg> [--product <id>] [--provider anthropic|openai]
          [--model-name <모델>] [--base-url <url>] [--instruction <추가 지시>] [--no-rag]
      분류 → 검색 → 답변 생성을 콘솔에서 확인합니다(발송하지 않음).
      API 키는 환경 변수 ANTHROPIC_API_KEY 또는 OPENAI_API_KEY에서 읽습니다.
```

### 폴더 구조 만들기

```powershell
TechSupportReply.Indexer.exe init-kb --root \server\KB
```

`products.json`(기본 제품 목록), 제품별 폴더와 `manuals`·`replies`·`faq`·`issues` 하위 폴더, 제품별 `_prompt.md` 템플릿, `_index`, `_models`, `README.md`를 만듭니다. **이미 있는 파일은 덮어쓰지 않습니다.**

## 3. products.json

제품군 목록과 분류 키워드를 정의합니다. 애드인은 공유 폴더의 이 파일을 읽습니다(읽지 못하면 로컬 캐시, 그것도 없으면 기본 목록을 쓰고 작업창에 경고를 표시합니다).

```json
{
  "products": [
    {
      "id": "ls-dyna",
      "displayName": "LS-DYNA",
      "folder": "LS-DYNA",
      "keywords": ["ls-dyna", "lsdyna", "*keyword", "*contact", "d3plot", "d3hsp", "messag", "binout"]
    },
    {
      "id": "_common",
      "displayName": "공통 (라이선스/설치)",
      "folder": "_common",
      "keywords": ["license", "라이선스", "ansyslmd", "lmutil", "flexnet", "설치", "install"]
    }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `id` | 제품 식별자. 색인 파일 이름(`<id>.sqlite`)과 `--product` 옵션에 쓰입니다. 만든 뒤에는 바꾸지 않는 것이 좋습니다. |
| `displayName` | 작업창 "제품군" 드롭다운에 보이는 이름 |
| `folder` | 공유 폴더 아래의 제품 폴더 이름 |
| `keywords` | 제품 판별용 키워드. 메일 제목·본문·첨부 파일 이름에서 찾아 점수를 매깁니다. 대소문자는 구분하지 않습니다. |

- 제품을 추가하려면 항목을 추가하고 폴더와 `_prompt.md`를 만든 뒤 색인을 실행합니다.
- `_common`은 모든 제품 검색에 함께 포함되며, 제품을 판별하지 못했을 때의 기본값입니다. 지우지 마세요.
- 전체 기본 목록은 `samples\kb\products.json`을 참고하세요.

## 4. 제품별 _prompt.md 작성 요령

`<제품 폴더>\_prompt.md`의 내용은 그 제품 문의에 답변을 생성할 때 **시스템 지침으로 그대로 전달**됩니다. 짧고 구체적으로 씁니다.

권장 구성:
- **어조·표기**: 키워드 카드·메뉴·옵션은 매뉴얼 표기(대소문자 포함)를 그대로 쓰기, 제품 정식 명칭 사용 등
- **문의 유형별로 요청할 파일**: 예) 해석 오류는 d3hsp, messag, 솔버 버전, SMP/MPP 여부. 라이선스는 서버 로그, 호스트 이름, 오류 코드
- **금지사항**: 확인되지 않은 버그·출시 일정 단정 금지, 다른 고객 사례 언급 금지 등
- **제품 특유 권고의 조건**: 예) "질량 스케일링을 권할 때는 질량 증가율을 glstat/matsum으로 확인하도록 안내"

예시(`samples\kb\LS-DYNA\_prompt.md`):

```markdown
# LS-DYNA 답변 지침

- 키워드 카드는 *CONTACT_AUTOMATIC_SURFACE_TO_SURFACE 처럼 전체 이름을 대문자로 씁니다.
- 해석 오류 문의에는 d3hsp, messag 파일과 LS-DYNA 버전(R13.1 등), SMP/MPP 여부를 요청합니다.
- 질량 스케일링(DT2MS)을 권할 때는 질량 증가율(%)을 glstat/matsum 으로 확인하도록 안내합니다.
```

기본 동작(근거에 없는 옵션·수치를 지어내지 않기, 불확실한 부분에 `[확인 필요]` 표시 등)은 애드인의 공통 지침에 이미 들어 있으므로 `_prompt.md`에 반복할 필요가 없습니다. `_prompt.md`는 색인 대상이 아니므로 수정한 뒤 색인을 다시 만들 필요는 없습니다. 팀원 PC는 공유 폴더와 동기화할 때(답변 생성 시 자동, 또는 설정의 [지금 동기화]) 이 파일을 로컬 캐시로 복사해 사용합니다.

## 5. 임베딩 모델(ONNX) 배치

임베딩은 로컬에서 bge-m3 int8 모델로 수행합니다. 문서 내용을 외부로 보내지 않습니다.

1. 모델 내려받기(약 570MB). Git Bash 등 bash에서 저장소 루트에서 실행합니다.
   ```bash
   bash tools/download_model.sh
   ```
   `models/bge-m3-int8/`에 `model.onnx`, `tokenizer.json`, `sentencepiece.bpe.model`이 내려받아집니다. 이미 받은 파일은 건너뜁니다.
2. 공유 폴더에 복사합니다. 최소한 다음 두 파일이 필요합니다.
   ```
   \server\KB\_models\bge-m3-int8\model.onnx
   \server\KB\_models\bge-m3-int8\sentencepiece.bpe.model
   ```
   (`tokenizer.json`은 있어도 되지만 사용하지 않습니다.)
3. 팀원 PC는 처음 검색할 때 이 폴더를 `%LOCALAPPDATA%\TechSupportReply\cache\models\bge-m3-int8`로 복사해 씁니다.

`index`는 기본적으로 `<RAG 루트>\_models\bge-m3-int8`을 사용합니다. 다른 폴더를 쓰려면 `--model <모델 폴더>` 옵션이나 환경 변수 `TSR_MODEL_DIR`을 지정합니다. 모델 폴더가 없으면 오류로 중단됩니다.

색인의 임베딩 모델 id가 팀원의 로컬 모델과 다르면 벡터 검색을 끄고 키워드(BM25) 검색만 사용하며 경고를 표시합니다.

## 6. 색인 실행

```powershell
# 모든 제품(바뀐 파일만 다시 임베딩)
TechSupportReply.Indexer.exe index --root \server\KB

# 한 제품만
TechSupportReply.Indexer.exe index --root \server\KB --product ls-dyna

# 전체 다시 만들기
TechSupportReply.Indexer.exe index --root \server\KB --product ls-dyna --full
```

- `--product`에는 `products.json`의 `id`를 씁니다.
- 증분 색인은 파일 크기·수정 시각·해시를 비교해 바뀐 파일만 다시 임베딩하고, 삭제된 파일의 청크는 제거합니다.
- 작업용 복사본은 기본 `%TEMP%\TechSupportReply-index`에 만들고(`--work <폴더>`로 변경), 완성된 색인만 `_index`에 원자적으로 게시합니다. 변경이 없으면 게시를 생략합니다.
- 결과로 제품별 추가/갱신/삭제/유지 개수, 버전, 읽지 못한 파일(`건너뜀`), 지원하지 않는 형식 개수가 출력됩니다.
- 읽지 못한 파일이 있어도 나머지는 색인되고, 읽지 못한 파일은 `건너뜀`으로 표시됩니다.

### 동작 확인

```powershell
TechSupportReply.Indexer.exe search --root \server\KB --product ls-dyna --query "initial penetration" --top 8
TechSupportReply.Indexer.exe reply  --root \server\KB --mail C:\temp\문의.eml --product ls-dyna
```

`search`는 애드인과 같은 방식으로 캐시를 동기화하고 검색 결과를 보여 줍니다. `reply`는 분류 → 검색 → 답변 생성을 콘솔에서 확인하며 **발송하지 않습니다**(API 키는 `ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY` 환경 변수).

### 작업 스케줄러 등록 (매일 02:00)

```
schtasks /Create /TN "TechSupportReply Index" /SC DAILY /ST 02:00 /TR "\"C:\Tools\TechSupportReply.Indexer\TechSupportReply.Indexer.exe\" index --root \server\KB"
```

실행 계정이 `\server\KB`에 쓰기 권한을 가져야 합니다. 계정을 지정하려면 `/RU 계정 /RP 암호`를 추가합니다.

## 7. 애드인 게시와 버전 올리기

PowerShell에서(Git Bash 아님):

```powershell
.\tools\publish-addin.ps1 -PublishDir \server\deploy\TechSupportReply
```

- 실행할 때마다 `publish\revision.txt`의 수정 번호가 1 올라가며, 팀원의 Outlook은 시작할 때 새 수정 번호를 감지해 자동 업데이트합니다.
- 이 저장소의 `publish\revision.txt`를 다른 PC에서 관리하면 번호가 뒤로 갈 수 있으니, 게시는 항상 같은 PC(또는 같은 저장소 복사본)에서 하세요.
- 설치 안내는 설치가이드.md를 참고하세요.

## 8. 인증서 관리

- 매니페스트 서명 인증서는 `tools\New-DevSigningCert.ps1`이 준비합니다. 기본은 개발용 자체 서명(`CN=TechSupportReply Dev (KOSTECH)`, 5년)이며 현재 사용자 인증서 저장소에 보관됩니다. 만료 30일 이내가 되면 새로 만듭니다.
- 지문은 `src\TechSupportReply.AddIn\Signing.user.props`에 기록됩니다(버전 관리 대상이 아닙니다).
- 공개 인증서는 `publish\TechSupportReply-signing.cer`로 내보내지며, 게시할 때 게시 폴더에도 복사됩니다. 팀 PC의 "신뢰할 수 있는 게시자"와 "신뢰할 수 있는 루트 인증 기관"에 배포하면 설치 경고가 사라집니다.
- 회사 코드 서명 인증서로 바꾸려면:
  ```powershell
  .\tools\New-DevSigningCert.ps1 -PfxPath C:\certs\company.pfx -PfxPassword (Read-Host "PFX 암호" -AsSecureString)
  ```
- **인증서를 바꾸면 기존 설치본이 업데이트되지 않을 수 있습니다.** 서명이 달라지면 팀원이 기존 항목을 제거하고 다시 설치해야 할 수 있으니 사전에 공지하세요.
- PFX 파일과 암호는 저장소에 넣지 않습니다.

## 9. 팀원 PC 설정 안내

팀원은 [설정] → 지식 폴더 탭의 **RAG 루트**에 `\server\KB`를 입력합니다. 같은 탭의 [지금 동기화]로 색인과 모델을 미리 캐시에 받을 수 있습니다. 공유 폴더에 접근할 수 없을 때는 기존 캐시를 사용합니다. 로그는 `%LOCALAPPDATA%\TechSupportReply\logs`에 있습니다.

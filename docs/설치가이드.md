# 설치 가이드 — Outlook에 "기술지원 답변 도우미" 추가하기

이 애드인은 Outlook Classic(데스크톱 Outlook)에서 기술지원 메일을 선택하면 제품군을 판별하고, 공유 지식 폴더를 검색해 **회신 초안**을 만들어 줍니다. 메일을 자동으로 보내지 않습니다. 초안을 검토한 뒤 직접 보냅니다.

설치 방법은 세 가지입니다.

| 방법 | 대상 | 특징 |
|---|---|---|
| A. ClickOnce(권장) | 팀원 전체 | 관리자가 한 번 게시하면 팀원은 `.vsto` 파일을 실행해 설치하고, 이후 Outlook을 시작할 때 자동으로 업데이트됩니다. |
| B. 수동 등록 | 개별 PC, ClickOnce를 쓰지 않을 때 | 스크립트가 파일 복사와 레지스트리 등록을 합니다. 관리자 권한이 필요 없습니다. |
| C. 개발자 | 개발 PC | Visual Studio에서 F5 또는 `build-addin.ps1` 실행 시 자동 등록됩니다. |

---

## 1. 사전 요구사항

1. **Outlook Classic x64**
   - 확인: Outlook → 파일 → Office 계정 → Outlook 정보. 창 제목 줄에 "64비트"가 보여야 합니다.
   - "새 Outlook"(웹 기반)과 웹 Outlook에서는 VSTO 애드인이 동작하지 않습니다.
2. **.NET Framework 4.8** (Windows 10/11에는 기본 포함)
3. **VSTO Runtime** (Office 2016 이상에 포함). 설치 여부는 아래 레지스트리 키로 확인합니다.
   ```
   HKLM\SOFTWARE\WOW6432Node\Microsoft\VSTO Runtime Setup\v4R
   ```
   키가 있고 `Version` 값이 보이면 설치된 것입니다. 없으면 Microsoft에서 "Visual Studio 2010 Tools for Office Runtime"을 받아 설치합니다.
4. (관리자·개발자 PC) **Visual Studio 2022**의 "Office/SharePoint 개발" 워크로드. 게시·빌드 스크립트가 사용합니다.

> 개발자 주의: 저장소 루트에서 `dotnet build` 또는 `dotnet test`만 실행하면 `.sln`을 집어 VSTO 프로젝트 때문에 실패합니다. 테스트는 `dotnet test tests/TechSupportReply.Tests`, 애드인 빌드는 `tools\build-addin.ps1`을 사용하세요.

## 2. 방법 A (권장): ClickOnce로 팀 배포

### 2-1. 관리자: 게시

**PowerShell**에서 실행합니다(Git Bash가 아님). 저장소 루트에서:

```powershell
.\tools\publish-addin.ps1 -PublishDir \server\deploy\TechSupportReply
```

- 매니페스트 서명 인증서가 없으면 `tools\New-DevSigningCert.ps1`이 자동으로 실행되어 개발용 자체 서명 인증서를 만듭니다(사용자 저장소에 저장, 유효기간 5년).
- 게시할 때마다 `publish\revision.txt`의 수정 번호가 1씩 올라갑니다. 이 번호가 ClickOnce의 업데이트 판단 기준입니다.
- 게시 폴더에는 `TechSupportReply.AddIn.vsto`, `Application Files` 폴더 등과 함께 공개 인증서 `TechSupportReply-signing.cer`도 복사됩니다.
- 설치 경로와 다른 주소(예: 웹 서버)에서 설치하게 하려면 `-InstallUrl <주소>`를 추가합니다(기본값은 `-PublishDir`과 같습니다).

### 2-2. 팀원: 설치

1. Outlook을 종료합니다.
2. 공유 폴더의 `\server\deploy\TechSupportReply\TechSupportReply.AddIn.vsto`를 더블클릭합니다.
3. 설치 확인 창에서 [설치]를 누릅니다.
4. Outlook을 시작하면 [홈] 탭에 "기술지원" 그룹이 나타납니다.

이후에는 Outlook을 시작할 때 새 버전이 있으면 자동으로 업데이트됩니다.

### 2-3. "게시자를 확인할 수 없습니다" 경고

자체 서명 인증서라서 설치할 때 이 경고가 뜹니다. 없애는 방법은 둘 중 하나입니다.

- **인증서 배포**: 게시 폴더의 `TechSupportReply-signing.cer`를 각 PC의 **"신뢰할 수 있는 게시자"**와 **"신뢰할 수 있는 루트 인증 기관"** 저장소에 넣습니다(그룹 정책으로 배포하거나, `.cer`를 더블클릭 → 인증서 설치 → 로컬 컴퓨터/현재 사용자 → 해당 저장소 선택).
- **회사 코드 서명 인증서 사용**: 회사 PFX 파일로 서명합니다.
  ```powershell
  $pw = Read-Host "PFX 암호" -AsSecureString
  .\tools\New-DevSigningCert.ps1 -PfxPath C:\certs\company.pfx -PfxPassword $pw
  ```
  인증서를 바꾼 뒤 다시 게시합니다.

참고: 공유 폴더(UNC 경로)에서 설치하려면 그 서버가 Windows의 **"로컬 인트라넷" 영역**에 속해야 합니다. 인터넷 영역으로 분류되면 설치가 차단될 수 있습니다(인터넷 옵션 → 보안 → 로컬 인트라넷 → 사이트 → 고급에 `file://server` 추가 또는 그룹 정책).

## 3. 방법 B: 수동 등록

빌드 폴더(`TechSupportReply.AddIn.vsto`가 있는 폴더)를 지정해 PowerShell에서 실행합니다.

```powershell
.\tools\install-addin.ps1 -Source \server\deploy\TechSupportReply\bin
```

- **Outlook을 먼저 종료해야 합니다.** 실행 중이면 "Outlook을 종료한 뒤 다시 실행하세요." 오류로 중단됩니다.
- 관리자 권한은 필요 없습니다.
- 설치 위치는 기본 `%LOCALAPPDATA%\Programs\TechSupportReply`입니다. 바꾸려면 `-Target <폴더>`를 지정합니다.

스크립트가 하는 일:
1. `-Source` 폴더를 설치 위치로 복사(robocopy `/MIR`).
2. `.vsto` 매니페스트의 서명 인증서 공개 키를 `HKCU\Software\Microsoft\VSTO\Security\Inclusion` 신뢰 목록에 등록(설치 확인 창 없이 로드).
3. `HKCU\Software\Microsoft\Office\Outlook\Addins\TechSupportReply.AddIn`에 `FriendlyName`, `Description`, `LoadBehavior=3`, `Manifest` 등록.

같은 내용을 레지스트리 파일로 직접 등록하려면(신뢰 목록 등록은 별도로 필요하므로 스크립트 사용을 권장합니다) 다음과 같습니다. `<사용자>`를 바꿔 넣으세요.

```
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Microsoft\Office\Outlook\Addins\TechSupportReply.AddIn]
"FriendlyName"="기술지원 답변 도우미"
"Description"="LS-DYNA·Ansys 기술지원 메일 회신 초안(자동 발송 없음)"
"LoadBehavior"=dword:00000003
"Manifest"="file:///C:/Users/<사용자>/AppData/Local/Programs/TechSupportReply/TechSupportReply.AddIn.vsto|vstolocal"
```

## 4. 방법 C: 개발자

- Visual Studio 2022에서 `TechSupportReply.sln`을 열고 `TechSupportReply.AddIn`을 시작 프로젝트로 정한 뒤 F5를 누릅니다.
- 또는 PowerShell에서 다음을 실행하면 빌드하면서 Outlook에 자동 등록됩니다(Debug 기본, Release는 `-Configuration Release`).
  ```powershell
  .\tools\build-addin.ps1
  ```
- 서명 인증서가 없으면 자동으로 만듭니다(`src\TechSupportReply.AddIn\Signing.user.props`에 지문 기록).
- `dotnet build`로는 VSTO 프로젝트를 빌드할 수 없습니다.

## 5. Outlook에서 활성화 확인

파일 → 옵션 → 추가 기능 → 관리: **COM 추가 기능** → [이동] → "기술지원 답변 도우미"에 체크가 되어 있는지 확인합니다. 체크하면 [홈] 탭에 "기술지원" 그룹이 나타납니다.

## 6. 문제 해결

- **LoadBehavior가 2로 바뀜**: Outlook이 로드에 실패했다는 뜻입니다. `HKCU\Software\Microsoft\Office\Outlook\Addins\TechSupportReply.AddIn`의 `LoadBehavior`를 3으로 되돌리고, 아래 로그와 로드 오류 표시로 원인을 확인하세요.
- **"사용 안 함 항목"에 들어감**: 파일 → 옵션 → 추가 기능 → 관리: **사용할 수 없는 항목** → [이동] → 애드인을 선택하고 [사용]을 누릅니다.
- **느린 애드인으로 자동 비활성화**: 다음 레지스트리 값을 추가하면 방지됩니다.
  ```
  HKCU\Software\Microsoft\Office\16.0\Outlook\Resiliency\DoNotDisableAddinList
    TechSupportReply.AddIn = DWORD 1
  ```
  조직 전체에는 그룹 정책의 "관리되는 추가 기능 목록"(Office 관리 템플릿)을 사용합니다.
- **로드 오류가 보이지 않음**: 시스템 환경 변수 `VSTO_SUPPRESSDISPLAYALERTS`를 `0`으로 설정하고 Outlook을 다시 시작하면 VSTO 로드 오류 창이 표시됩니다.
- **로그 위치**: `%LOCALAPPDATA%\TechSupportReply\logs\yyyy-MM-dd.log` (날짜별 파일). 메일 본문과 API 키는 기록하지 않습니다.
- **환경 변수로 API 키를 추가했는데 인식하지 못함**: 키는 프로세스 → 사용자 → 시스템 순서로 읽으므로 Outlook을 시작한 뒤 추가해도 동작합니다. 그래도 문제가 있으면 Outlook을 완전히 종료(작업 관리자에서 OUTLOOK.EXE 확인)한 뒤 다시 시작하세요. 단, 프로필이 처음 만들어질 때(`ANTHROPIC_WORKSPACE_ID` 포함)만 읽는 값이 있습니다. 자세한 내용은 사용자가이드를 참고하세요.
- **설치 위치·설정 위치**: 설정 `%APPDATA%\TechSupportReply\settings.json`, API 키 `%APPDATA%\TechSupportReply\secrets.dat`(DPAPI 암호화), 색인 캐시·모델 `%LOCALAPPDATA%\TechSupportReply\cache`.

## 7. 제거

- **방법 A**: 제어판(설정 → 앱) → 프로그램 제거 → "기술지원 답변 도우미"(ClickOnce로 설치된 항목).
- **방법 B**: Outlook을 종료하고 실행합니다.
  ```powershell
  .\tools\install-addin.ps1 -Uninstall
  ```
  이 스크립트가 등록한 키와 신뢰 목록 항목만 지우고 설치 폴더를 삭제합니다. 레지스트리의 등록이 이 설치를 가리키지 않으면(예: 개발 빌드) 그 등록은 그대로 둡니다. 설정(`%APPDATA%\TechSupportReply`)과 캐시(`%LOCALAPPDATA%\TechSupportReply`)는 남겨 둡니다. 완전히 지우려면 두 폴더를 직접 삭제하세요. 설치 위치를 바꿨다면 `-Target`을 같은 값으로 지정합니다.
- **개발 PC**: Visual Studio에서 [솔루션 정리]를 하거나 `HKCU\Software\Microsoft\Office\Outlook\Addins\TechSupportReply.AddIn` 키를 삭제합니다.
